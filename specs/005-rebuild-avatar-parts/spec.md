# Feature Specification: 모듈형 픽셀 아바타 재구성

**Feature Branch**: `005-rebuild-avatar-parts`

**Created**: 2026-08-31

**Status**: Draft

**Input**: User description: "현재 아바타는 해상도는 좋아졌지만 머리, 몸, 옷, 아이템의 비율과 신체 표현이 서로 맞지 않고 아이템이 얼굴과 몸을 가린다. 공통 골격과 명확한 파츠 경계를 기준으로 전신 픽셀 아바타를 다시 구성한다. 먼저 모바일 로비에서 대표 조합 4개를 검증하고 승인한 뒤 전체 조합으로 확장한다. 기존 사용자의 대화 기반 해시, 클래스, 아이템과 결정적 배정 결과는 유지한다."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 대표 아바타 조합을 먼저 승인하기 (Priority: P1)

운영자는 전체 에셋을 다시 만들기 전에 서로 다른 체형, 머리 모양, 옷과 아이템 특성을 담은 대표 조합 4개를 휴대폰 로비에서 확인한다. 얼굴과 전신이 자연스럽게 보이고, 아이템이 캐릭터를 가리지 않으며, 각 부분이 하나의 캐릭터처럼 이어지는지 확인한 뒤 전체 확장을 승인한다.

**Why this priority**: 지금 문제는 해상도보다 파츠끼리 맞지 않는 데 있다. 소수의 대표 조합으로 기준을 먼저 확정하지 않으면 같은 문제를 모든 에셋에 반복하게 된다.

**Independent Test**: 대표 조합 4개만 준비한 상태에서 360px 너비의 휴대폰 로비와 진행자 화면에 표시하고, 아래 승인 기준을 전부 통과하는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 크기와 형태가 서로 다른 머리 모양, 옷과 아이템을 포함한 대표 조합 4개, **When** 운영자가 휴대폰 로비에서 각 조합을 확인하면, **Then** 모든 조합에서 얼굴, 몸, 손, 발이 겹치거나 중복되지 않고 하나의 전신 캐릭터로 보인다.
2. **Given** 손에 들거나 몸 옆에 배치되는 아이템이 포함된 대표 조합, **When** 아바타가 가장 작은 참가자용 크기로 표시되면, **Then** 아이템의 종류를 알아볼 수 있으면서 얼굴을 가리지 않고 몸통의 핵심 형태를 과도하게 가리지 않는다.
3. **Given** 대표 조합 검토가 끝난 상태, **When** 하나라도 승인 기준을 통과하지 못하면, **Then** 전체 에셋 확장으로 넘어가지 않고 실패한 조합과 이유가 검토 기록에 남는다.
4. **Given** 대표 조합 4개가 모든 승인 기준을 통과한 상태, **When** 운영자가 승인하면, **Then** 같은 기준을 전체 파츠에 적용할 수 있는 승인 기준선이 확정된다.

---

### User Story 2 - 참가자가 선명하고 자연스러운 내 캐릭터 보기 (Priority: P1)

참가자는 가입이나 재접속 뒤 로비에서 자신에게 이미 정해진 프로필을 그대로 유지하면서, 머리부터 발끝까지 선명한 픽셀 캐릭터를 본다. 머리, 몸, 옷과 아이템이 따로 붙인 그림처럼 보이지 않고 한 캐릭터로 읽혀야 한다.

**Why this priority**: 아바타는 참가자가 서비스에 들어오자마자 마주치는 핵심 결과다. 클래스와 아이템 설명이 재미있어도 캐릭터가 어색하면 대화 기반 아바타라는 인상이 무너진다.

**Independent Test**: 기존 참가자 계정으로 모바일 로비에 접속해 프로필 정보가 바뀌지 않았는지, 전신과 아이템이 선명하고 자연스럽게 표시되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 기존에 대화 해시, 클래스, 상태와 아이템이 확정된 참가자, **When** 새 아바타 표현이 적용된 로비에 접속하면, **Then** 기존 프로필 값은 그대로이고 시각 표현만 새 기준으로 바뀐다.
2. **Given** 참가자가 360px 너비의 휴대폰에서 로비를 보고 있는 상태, **When** 아바타 카드가 표시되면, **Then** 캐릭터 전체가 카드 안에 잘리지 않고 픽셀 경계가 흐려지지 않은 상태로 보인다.
3. **Given** 긴 머리, 큰 장비 또는 넓은 옷처럼 공간을 많이 쓰는 조합, **When** 로비에 표시되면, **Then** 얼굴 식별 영역이 보이고 아이템과 의상이 손, 발 또는 얼굴을 중복해서 그리지 않는다.
4. **Given** 같은 참가자가 로그아웃 후 다시 로그인한 상태, **When** 로비를 다시 열면, **Then** 이전과 같은 프로필과 같은 아바타 조합을 본다.

---

### User Story 3 - 모든 조합에서 같은 품질 유지하기 (Priority: P2)

운영자는 승인된 대표 조합의 비율과 역할 구분이 전체 아바타 조합에도 그대로 적용되기를 원한다. 조합에 따라 손이 두 개 더 생기거나 신발이 겹치고, 머리카락이 얼굴 전체를 덮는 식의 예외가 없어야 한다.

**Why this priority**: 대표 조합만 좋아 보여도 실제 참가자에게 배정된 다른 조합이 깨지면 행사에서 사용할 수 없다.

**Independent Test**: 제공 가능한 모든 파츠 조합을 한 화면 또는 검토 자료에서 확인해 중복 신체, 가림, 잘림과 위치 이탈이 없는지 검사한다.

**Acceptance Scenarios**:

1. **Given** 승인된 기준으로 전체 파츠가 준비된 상태, **When** 가능한 조합을 전수 검토하면, **Then** 신체 부위 중복, 파츠 위치 이탈, 카드 밖 잘림과 빈 이미지가 한 건도 없다.
2. **Given** 크고 세로로 긴 아이템과 작고 가로로 넓은 아이템, **When** 서로 다른 머리와 옷에 결합하면, **Then** 각 아이템은 알아볼 수 있는 크기를 유지하면서 얼굴을 가리지 않는다.
3. **Given** 기존 참가자 전체의 확정 프로필, **When** 새 시각 표현으로 전환하면, **Then** 참가자별 해시, 클래스, 상태, 아이템 이름과 조합 선택 결과가 바뀌지 않는다.

---

### User Story 4 - 일부 에셋 문제에도 완성된 대체 캐릭터 보기 (Priority: P3)

참가자는 특정 파츠를 불러오지 못하거나 준비되지 않은 조합을 배정받더라도 몸 일부만 보이는 깨진 캐릭터 대신 완성된 기본 캐릭터를 본다. 운영자는 어떤 파츠에 문제가 있었는지 확인할 수 있다.

**Why this priority**: 행사 중 깨진 이미지나 몸 일부만 있는 캐릭터는 즉시 눈에 띈다. 전체 서비스를 막지 않고도 완성된 화면을 유지할 최소 복구 수단이 필요하다.

**Independent Test**: 각 파츠 종류를 하나씩 사용할 수 없게 만든 뒤 참가자 로비와 운영 검토 화면에서 완성된 대체 캐릭터와 문제 식별 정보가 제공되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 필요한 파츠 하나를 사용할 수 없는 참가자 조합, **When** 로비가 아바타를 표시하면, **Then** 부분적으로 깨진 조합 대신 얼굴과 전신이 갖춰진 기본 캐릭터가 표시된다.
2. **Given** 대체 캐릭터가 표시된 상태, **When** 운영자가 문제를 확인하면, **Then** 참가자의 비공개 대화 내용이나 인증 정보를 노출하지 않고 실패한 파츠 종류와 식별자를 알 수 있다.

### Edge Cases

- 머리 모양이 얼굴 아래나 어깨 뒤까지 길어도 얼굴의 눈과 중심 표정은 가려지지 않아야 한다.
- 가로로 넓거나 세로로 긴 아이템도 캐릭터 카드 밖으로 잘리거나 발밑 기준선을 밀어내지 않아야 한다.
- 옷이 긴 소매나 긴 기장을 가져도 기본 몸의 손과 발을 중복해서 표현하지 않아야 한다.
- 같은 조합이 참가자 로비, 관리자 목록과 진행자 화면에서 서로 다른 비율이나 위치로 보여서는 안 된다.
- 고해상도 화면과 일반 휴대폰 화면에서 픽셀 경계가 흐려지거나 부분적으로 부드럽게 보간되어서는 안 된다.
- 네트워크가 느리거나 일부 이미지가 늦게 도착해도 파츠가 하나씩 흩어진 미완성 상태를 최종 결과처럼 오래 보여서는 안 된다.
- 아직 새 기준으로 준비되지 않은 과거 조합이 남아 있을 때 기존 참가자의 프로필 데이터 자체를 새 값으로 바꾸어 문제를 숨겨서는 안 된다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 모든 전신 아바타가 공유하는 기준 자세, 얼굴 위치, 몸통 범위, 손 위치, 발 위치와 바닥 기준을 정의하고 모든 시각 파츠에 동일하게 적용해야 한다.
- **FR-002**: 머리 모양은 머리카락과 머리 장식만, 몸은 피부와 기본 신체만, 의상은 옷만, 아이템은 소지품만 표현해야 하며 서로의 역할에 속하는 손, 발, 얼굴, 피부, 신발 또는 신체 윤곽을 중복해서 포함하지 않아야 한다.
- **FR-003**: 결합된 아바타는 얼굴과 전신을 하나의 일관된 픽셀 표현으로 보여야 하며, 파츠별 선명도와 픽셀 크기가 눈에 띄게 달라서는 안 된다.
- **FR-004**: 시스템은 전체 확장 전에 긴 머리와 짧은 머리, 넓은 옷과 좁은 옷, 크기와 형태가 다른 아이템을 포함하는 대표 조합 4개를 제공해야 한다.
- **FR-005**: 대표 조합은 모바일 로비, 관리자 검토 화면과 진행자 화면에서 얼굴 가시성, 신체 중복, 아이템 가림, 파츠 정렬, 잘림과 선명도를 검토할 수 있어야 한다.
- **FR-006**: 시스템은 대표 조합 4개가 모두 승인되기 전까지 승인되지 않은 기준으로 전체 에셋을 완성된 것으로 취급하지 않아야 한다.
- **FR-007**: 모든 아이템은 가장 작은 참가자용 표시 크기에서도 종류를 알아볼 수 있어야 하며, 얼굴 영역을 가리거나 몸통 가시 영역의 30%를 넘게 가리지 않아야 한다.
- **FR-008**: 머리 모양과 머리 장식은 눈과 중심 표정을 포함한 얼굴 식별 영역을 가리지 않아야 한다.
- **FR-009**: 시스템은 가능한 모든 제공 조합을 검토할 수 있는 자료를 제공하고, 각 조합에서 신체 중복, 위치 이탈, 잘림, 빈 파츠와 과도한 가림 여부를 확인할 수 있어야 한다.
- **FR-010**: 새 시각 표현은 기존 참가자의 대화 기반 해시, 클래스, 상태, 아이템 이름과 결정적으로 선택된 조합 값을 변경하지 않아야 한다.
- **FR-011**: 같은 참가자와 같은 조합은 재접속, 새로고침, 참가자 로비, 관리자 화면과 진행자 화면에서 같은 모습으로 표시되어야 한다.
- **FR-012**: 시스템은 참가자용 핵심 아바타를 360px 너비의 휴대폰에서 카드 밖 잘림이나 가로 스크롤 없이 전신으로 보여야 한다.
- **FR-013**: 아바타는 지원되는 화면 크기에서 픽셀 경계가 선명하게 유지되어야 하며 서로 다른 파츠에 일관되지 않은 흐림이나 보간이 나타나서는 안 된다.
- **FR-014**: 필요한 파츠를 사용할 수 없을 때 시스템은 일부 파츠만 보이는 결과 대신 얼굴과 전신이 완성된 기본 캐릭터를 표시해야 한다.
- **FR-015**: 운영자는 대체 캐릭터가 사용된 경우 민감한 참가자 정보 없이 실패한 파츠 종류와 식별자를 확인할 수 있어야 한다.
- **FR-016**: 사용한 픽셀 에셋의 출처, 제작 방식과 배포 가능 조건은 전체 확장 승인 전에 기록되어야 한다.
- **FR-017**: 이번 구간은 대화 분석, 해시 생성, 참가자 프로필 배정 규칙, 질문·답변 흐름과 미니게임을 변경하지 않아야 한다.

### Key Entities

- **아바타 기준선**: 모든 파츠가 공유하는 전신 자세와 얼굴, 몸통, 손, 발, 아이템 위치 및 시각 품질 기준이다.
- **아바타 파츠**: 몸, 머리 모양, 의상, 아이템처럼 하나의 시각 역할만 담당하며 공통 기준선에 맞춰 결합되는 표현 단위다.
- **아바타 조합**: 참가자에게 이미 결정된 파츠 선택 값과 이를 결합해 보이는 최종 전신 캐릭터다.
- **대표 검토 조합**: 서로 다른 형태와 가림 위험을 의도적으로 포함해 전체 확장 전에 승인받는 4개의 조합이다.
- **조합 검토 기록**: 조합별 얼굴 가시성, 신체 중복, 아이템 가림, 정렬, 잘림, 선명도와 승인 여부를 남긴 결과다.
- **기본 대체 캐릭터**: 필요한 파츠를 사용할 수 없을 때 부분적으로 깨진 결과를 대신하는 완성된 전신 캐릭터다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 대표 조합 4개를 360px 모바일 로비, 관리자 검토 화면과 진행자 화면에서 확인했을 때 얼굴 가림, 신체 중복, 파츠 위치 이탈, 카드 밖 잘림과 흐린 픽셀 경계가 0건이다.
- **SC-002**: 대표 조합 4개 모두 운영자의 시각 승인 기준을 한 번에 확인할 수 있고, 승인되지 않은 조합은 전체 확장 전에 명확히 구분된다.
- **SC-003**: 제공되는 모든 아바타 조합을 전수 검토했을 때 중복된 손·발·얼굴·신발, 빈 파츠, 잘림과 기준 위치 이탈이 0건이다.
- **SC-004**: 제공되는 아이템을 이름표 없이 가장 작은 참가자용 표시 크기로 보았을 때 운영자가 100% 올바르게 구분하고, 얼굴을 가리는 아이템은 0개다.
- **SC-005**: 아이템이 포함된 모든 조합에서 아이템이 가리는 몸통 가시 영역은 30% 이하이고, 눈과 중심 표정은 100% 보인다.
- **SC-006**: 기존 참가자 표본과 전체 저장 프로필을 비교했을 때 대화 기반 해시, 클래스, 상태, 아이템 이름과 조합 선택 값의 변경은 0건이다.
- **SC-007**: 같은 참가자를 재접속과 새로고침 뒤 참가자, 관리자, 진행자 화면에서 각각 확인했을 때 서로 다른 모습이 나타나는 경우는 0건이다.
- **SC-008**: 각 파츠 종류를 사용할 수 없는 상황을 검증했을 때 부분적으로 깨진 아바타 노출은 0건이고, 완성된 기본 캐릭터 표시와 운영자 식별 정보 제공 성공률은 100%다.
- **SC-009**: 정상적인 행사 네트워크 환경에서 참가자 로비 방문의 95%는 2초 안에 완성된 아바타를 표시한다.

## Assumptions

- `003`과 `004`에서 확정된 대화 기반 프로필의 해시, 클래스, 상태, 아이템 이름과 결정적 배정 규칙은 이미 운영 데이터로 사용 중이며 이번 구간에서는 바꾸지 않는다.
- 운영자가 대표 조합 4개의 최종 시각 승인자이며, 네 조합이 모두 통과한 뒤에만 전체 파츠 제작과 교체를 진행한다.
- 현재 제공 중인 파츠 종류와 조합 수를 유지하는 것이 기본이며, 새 종류를 추가하는 일은 이번 범위에 포함하지 않는다.
- 참가자가 가장 자주 보는 360px 너비의 모바일 로비를 첫 승인 기준으로 삼고, 관리자와 진행자 화면에서도 같은 캐릭터 정체성을 유지한다.
- 픽셀 아트의 세부 미술 스타일은 기존 서비스의 어두운 레트로 게임 화면과 어울리게 유지하되, 구체적인 제작 도구와 파일 구성은 계획 단계에서 정한다.
- 외부 에셋을 활용할 수는 있지만 배포 가능한 조건과 출처가 확인된 것만 사용한다.
