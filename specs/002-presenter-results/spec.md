# Feature Specification: 진행자 결과 발표 화면

**Feature Branch**: `미생성 (before_specify 훅 없음)`

**Created**: 2026-08-30

**Status**: Draft

**Input**: User description: "이제 관리자가 진행할 때 사용할 페이지가 필요하다. 참가자가
제출한 3주년 답변 결과를 행사 중에 확인하고 하나씩 공개하며 진행할 수 있어야 한다."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 답변을 하나씩 골라 공개하기 (Priority: P1)

진행자는 관리자 권한으로 현재 질문의 제출 현황과 답변을 확인한다. 발표할 답변을 직접
고르거나 아직 공개하지 않은 답변 중 하나를 무작위로 골라, 참석자들에게 한 장씩 보여주며
이야기를 이어 간다. 답변 작성자의 닉네임은 기본적으로 숨겨지고 진행자가 필요할 때만
공개한다.

**Why this priority**: 참가자가 남긴 기록을 실제 모임의 대화로 이어 주는 핵심 장면이다.
이 흐름만 완성해도 진행자는 별도 문서나 화면 전환 없이 답변 공유 시간을 운영할 수 있다.

**Independent Test**: 제출 답변이 세 개 이상 있는 행사에서 진행자가 현황을 확인하고,
익명 답변 하나를 무작위로 공개한 뒤 작성자 닉네임을 공개하는 과정만으로 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 답변을 제출한 참가자와 제출하지 않은 참가자가 섞여 있을 때, **When** 진행자가
   결과 화면을 열면, **Then** 전체 입장 인원과 제출·미제출 인원 및 제출된 답변만 확인한다.
2. **Given** 아직 공개하지 않은 답변이 있을 때, **When** 진행자가 무작위 공개를 선택하면,
   **Then** 그중 한 답변이 선택되어 닉네임을 숨긴 채 발표 화면에 표시된다.
3. **Given** 익명으로 표시 중인 답변, **When** 진행자가 작성자 공개를 선택하면, **Then**
   해당 참가자의 닉네임과 캐릭터가 답변과 함께 표시된다.
4. **Given** 진행자가 특정 답변을 직접 선택했을 때, **When** 공개를 확정하면, **Then**
   선택하지 않은 답변이 대신 노출되지 않고 해당 답변만 발표 화면에 표시된다.

### User Story 2 - 발표 순서와 진행 상태 이어가기 (Priority: P2)

진행자는 이미 공개한 답변과 아직 공개하지 않은 답변을 구분하고 이전·다음 답변으로
이동한다. 실수로 페이지를 새로고침하거나 잠시 나갔다 돌아와도 현재 공개 중인 답변과
진행 상태가 복구된다. 발표 중 새로 제출된 답변도 기존 순서를 망가뜨리지 않고 후보에
추가된다.

**Why this priority**: 행사 중 새로고침 한 번으로 어디까지 진행했는지 잃어버리면 실제
사용이 어렵다. 반복 공개를 피하면서도 진행자가 필요할 때 다시 볼 수 있어야 한다.

**Independent Test**: 여러 답변을 공개한 뒤 페이지를 새로고침하고, 현재 답변·공개 여부·
이전 답변 이력이 그대로 복구되는지 확인할 수 있다.

**Acceptance Scenarios**:

1. **Given** 답변 두 개를 차례로 공개한 상태, **When** 진행자가 결과 화면을 새로고침하면,
   **Then** 현재 답변과 두 답변의 공개 완료 상태가 그대로 복구된다.
2. **Given** 공개 완료 답변과 미공개 답변이 함께 있을 때, **When** 무작위 공개를 반복하면,
   **Then** 미공개 답변을 모두 한 번씩 보기 전에는 완료된 답변이 다시 선택되지 않는다.
3. **Given** 이미 공개한 답변, **When** 진행자가 목록이나 이전 이동으로 다시 선택하면,
   **Then** 해당 답변을 의도적으로 다시 발표할 수 있다.
4. **Given** 발표가 진행 중일 때 참가자가 새 답변을 저장하면, **When** 결과 현황이
   갱신되면, **Then** 기존 공개 상태는 유지되고 새 답변은 미공개 후보로 추가된다.

### User Story 3 - 프로젝터에 안전하게 보여주기 (Priority: P3)

진행자는 조작 버튼과 참가자 전체 목록이 보이지 않는 발표 전용 화면을 프로젝터에 띄운다.
이 화면에는 현재 질문과 공개하기로 한 답변만 크게 표시되며, 진행자 화면에서 답변을 바꾸거나
작성자를 공개하면 발표 화면도 따라 바뀐다.

**Why this priority**: 관리자 조작 화면을 그대로 공유하면 아직 공개하지 않은 답변과 운영
정보가 참석자에게 보일 수 있다. 발표에 필요한 내용만 크게 보여주는 별도 화면이 필요하다.

**Independent Test**: 진행자 화면과 발표 화면을 서로 다른 창에 열고 답변 선택, 작성자 공개,
다음 답변 이동이 발표 화면에 반영되는지 확인할 수 있다.

**Acceptance Scenarios**:

1. **Given** 관리자 권한으로 연 발표 화면, **When** 아직 답변을 공개하지 않았으면,
   **Then** 질문과 대기 상태만 보이고 답변 목록이나 PIN 복구 기능은 보이지 않는다.
2. **Given** 발표 화면이 열려 있을 때, **When** 진행자가 다른 답변을 공개하면, **Then**
   발표 화면은 별도 새로고침 없이 새 답변으로 전환된다.
3. **Given** 1,000자에 가까운 긴 답변, **When** 일반적인 프로젝터 화면에 표시하면,
   **Then** 글자가 잘리거나 조작 버튼과 겹치지 않고 전체 내용을 읽을 방법이 제공된다.
4. **Given** 관리자 권한이 없는 사람, **When** 진행자 또는 발표 화면 주소로 접근하면,
   **Then** 답변 전문을 볼 수 없고 관리자 입장 화면으로 안내된다.

### Edge Cases

- 제출 답변이 하나도 없으면 오류 화면 대신 현재 제출 현황과 기다릴 수 있는 안내를 보여준다.
- 미공개 답변을 모두 발표한 뒤 무작위 공개를 누르면 자동으로 반복하지 않고, 모두 공개했다는
  상태와 의도적으로 다시 시작할 방법을 보여준다.
- 진행자가 현재 답변을 공개한 뒤 참가자가 같은 답변을 수정해도 화면 한가운데의 내용이
  말하는 도중 갑자기 바뀌지 않는다. 다음에 다시 선택하면 최신 성공본을 사용한다.
- 참가자의 답변 저장과 진행자의 공개 동작이 거의 동시에 일어나도 다른 참가자의 닉네임이나
  캐릭터가 답변에 잘못 연결되지 않는다.
- 두 개의 진행자 창에서 거의 동시에 다른 답변을 선택하면 마지막으로 성공한 진행 상태가
  기준이 되고 두 창 모두 그 상태를 다시 확인할 수 있다.
- 관리자 세션이 만료되면 현재 화면에 남은 비공개 답변을 계속 탐색할 수 없고 다시 인증하도록
  안내한다.
- 발표 화면 연결이 잠시 끊기면 마지막으로 정상 수신한 슬라이드를 유지하면서 연결 상태를
  알리고, 복구 뒤 현재 진행 상태로 맞춘다.
- 답변 안의 긴 영문, URL, 줄바꿈, 이모지는 레이아웃 밖으로 넘치거나 다른 화면 요소로
  해석되지 않고 작성된 텍스트로 표시된다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 결과 진행 기능은 기존 관리자 권한을 확인받은 진행자만 사용할 수 있어야 한다.
- **FR-002**: 진행자는 현재 행사의 전체 입장 인원, 답변 제출 인원, 미제출 인원을 한 화면에서
  확인할 수 있어야 한다.
- **FR-003**: 진행자는 현재 공개 중인 질문과 그 질문에 제출된 답변의 최신 성공본을 확인할
  수 있어야 한다.
- **FR-004**: 제출하지 않은 참가자는 답변 후보에 포함해서는 안 된다.
- **FR-005**: 진행자는 특정 답변을 직접 선택해 발표할 수 있어야 한다.
- **FR-006**: 진행자는 아직 공개하지 않은 답변 중 하나를 무작위로 선택할 수 있어야 한다.
- **FR-007**: 무작위 선택은 모든 미공개 답변이 한 번씩 선택되기 전까지 공개 완료 답변을
  자동으로 다시 선택해서는 안 된다.
- **FR-008**: 답변은 처음 공개할 때 작성자 닉네임과 신원을 기본적으로 숨겨야 한다.
- **FR-009**: 진행자는 현재 답변의 작성자 닉네임과 캐릭터를 명시적인 동작으로 공개하거나
  다시 숨길 수 있어야 한다.
- **FR-010**: 진행자는 이전 답변, 다음 답변, 특정 완료 답변으로 이동해 이미 본 답변을
  의도적으로 다시 발표할 수 있어야 한다.
- **FR-011**: 서비스는 답변별 공개 완료 여부와 공개 순서를 진행자에게 구분해 보여줘야 한다.
- **FR-012**: 현재 공개 중인 답변, 표시 중인 내용, 작성자 공개 여부, 공개 완료 상태와 순서는
  페이지 새로고침, 서비스 재시작, 재배포 뒤에도 복구되어야 한다.
- **FR-013**: 발표 중 새로 제출된 답변은 기존 진행 상태를 초기화하지 않고 미공개 후보에
  추가되어야 한다.
- **FR-014**: 현재 표시 중인 답변은 참가자가 수정하더라도 진행자가 다른 답변으로 이동하거나
  다시 선택하기 전까지 발표 도중 자동으로 내용이 바뀌어서는 안 된다.
- **FR-015**: 서비스는 조작 기능과 전체 답변 목록을 제외하고 현재 질문과 공개 답변만 보여주는
  발표 전용 화면을 제공해야 한다.
- **FR-016**: 발표 화면은 진행자 화면의 현재 답변, 작성자 공개 여부와 대기 상태 변경을
  자동으로 반영해야 한다.
- **FR-017**: 발표 화면은 일반적인 프로젝터 화면과 전체 화면 사용에서 질문, 답변, 선택적으로
  공개된 닉네임과 캐릭터를 읽기 쉽게 표시해야 한다.
- **FR-018**: 긴 답변, 줄바꿈, URL, 이모지를 내용 손실이나 화면 이탈 없이 표시해야 한다.
- **FR-019**: 결과 진행의 모든 주요 동작은 명확한 텍스트 라벨과 키보드 조작 및 보이는
  포커스 상태를 제공해야 한다.
- **FR-020**: 관리자 권한이 없는 참가자나 방문자는 결과 목록, 답변 전문, 발표 화면을 열람할
  수 없어야 한다.
- **FR-021**: 진단 기록에는 답변 전문, 세션 정보 또는 아직 공개하지 않은 참가자 신원을
  남겨서는 안 된다.
- **FR-022**: 이 기능은 참가자의 원본 답변을 수정하거나 삭제하지 않고 발표 상태만 관리해야
  한다.
- **FR-023**: 기존 참가자 현황 확인과 PIN 초기화 기능은 결과 진행 기능을 추가한 뒤에도
  그대로 사용할 수 있어야 한다.

### Key Entities

- **발표 세션**: 한 행사에서 진행 중인 답변 발표의 현재 상태다. 현재 질문, 현재 슬라이드,
  작성자 공개 여부, 시작 및 최근 변경 시점을 가진다.
- **발표 항목**: 제출 답변이 발표 세션에서 어떻게 사용됐는지를 나타낸다. 원본 답변과
  연결되며 발표 당시 표시 내용, 공개 완료 여부, 공개 순서를 가진다.
- **발표 화면 상태**: 참석자에게 지금 보여 줄 대기·답변·작성자 공개 상태를 나타낸다.
- **답변**: 기존 기능에서 참가자가 저장한 원본 기록이다. 발표 항목은 이를 참조하지만 원본을
  변경하지 않는다.
- **진행자 권한**: 결과 열람, 발표 선택, 작성자 공개와 진행 상태 변경을 허용하는 기존
  관리자 접근 권한이다.

### Scope Boundaries

**이번 구간에 포함**:

- 현재 단일 질문의 전체·제출·미제출 현황
- 관리자 전용 답변 결과 목록
- 특정 답변 선택과 미공개 답변 무작위 선택
- 익명 기본 표시와 진행자의 작성자 공개
- 이전·다음 이동, 공개 완료 구분, 의도적인 재공개
- 새로고침과 재시작 뒤 발표 상태 복구
- 새 제출 답변 자동 반영
- 프로젝터용 발표 전용 화면

**이번 구간에서 제외**:

- 질문 생성, 수정, 여러 질문의 순서 관리
- 답변 원문 수정, 삭제, 검열
- 참가자가 다른 참가자의 답변을 자신의 기기에서 둘러보는 기능
- 공개 투표, 좋아요, 점수, 순위와 미니게임
- 여러 진행자의 역할 구분과 정교한 동시 편집 잠금
- 행사 종료 후 외부 공개 아카이브와 소셜 공유
- 답변의 자동 요약, 감정 분석 또는 AI 추천

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 진행자는 관리자 입장 후 30초 안에 전체·제출·미제출 인원과 첫 발표 답변을
  확인할 수 있다.
- **SC-002**: 처음 사용하는 진행자도 별도 설명 없이 1분 안에 익명 답변을 하나 공개하고,
  작성자를 공개한 뒤 다음 답변으로 이동할 수 있다.
- **SC-003**: 답변 30개를 무작위로 끝까지 공개했을 때 의도적인 재공개 전에는 같은 답변이
  중복 선택되지 않고 모든 답변이 정확히 한 번씩 포함된다.
- **SC-004**: 진행 상태를 만든 뒤 페이지 새로고침, 서비스 재시작, 재배포를 각각 수행해도
  현재 답변과 공개 이력 및 작성자 공개 상태가 100% 복구된다.
- **SC-005**: 참가자의 새 답변 저장과 진행 상태 변경은 정상 연결에서 5초 안에 진행자 및
  발표 화면에 반영된다.
- **SC-006**: 1,366×768 이상 발표 화면에서 1자부터 1,000자까지의 답변을 화면 요소가
  겹치거나 내용이 잘리지 않은 상태로 끝까지 읽을 수 있다.
- **SC-007**: 키보드만 사용하는 진행자가 답변 선택, 무작위 공개, 작성자 공개, 이전·다음
  이동과 발표 화면 진입을 모두 완료할 수 있다.
- **SC-008**: 관리자 권한이 없는 접근 시도에서는 제출 답변 전문과 발표 진행 상태가 한 건도
  노출되지 않는다.
- **SC-009**: 연결 중단, 세션 만료, 답변 없음, 모든 답변 공개 완료 상황을 만난 테스트
  진행자 전원이 화면 안내만으로 다음 행동을 결정할 수 있다.

## Assumptions

- 기존 `001-event-core-flow`의 행사, 질문, 참가자, 답변, 캐릭터와 관리자 인증을 그대로
  사용한다.
- 이번 행사에는 한 번에 하나의 공개 질문과 최대 30개의 제출 답변이 있다.
- 행사 진행을 조작하는 주 진행자는 한 명이며, 같은 계정으로 연 발표 화면이나 보조 창은
  현재 상태를 따라가는 용도로 사용한다.
- 답변은 진행 중에도 참가자가 수정할 수 있다. 현재 발표 중인 문구는 갑자기 바꾸지 않고,
  다시 선택할 때 최신 성공본을 사용한다.
- 닉네임은 진행자가 명시적으로 공개할 때만 참석자 화면에 나타난다. 공개 여부 판단은
  진행자가 행사 분위기와 참가자의 기대를 고려해 수행한다.
- 프로젝터 또는 공유 화면은 관리자가 통제하는 브라우저에서 연다. 공개 링크를 가진 누구나
  들어오는 별도 무인 디스플레이는 이번 범위에 포함하지 않는다.
- 자동 반영은 행사 진행에 충분히 빠르면 되며, 별도의 실시간 통신 기반 기능 자체는 요구하지
  않는다.
