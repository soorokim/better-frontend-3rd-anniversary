# Feature Specification: 3주년 행사 기본 참여 흐름

**Feature Branch**: `미생성 (before_specify 훅 없음)`

**Created**: 2026-08-30

**Status**: Draft

**Input**: User description: "참가자는 공통 초대 코드로 입장하고 닉네임과 개인 PIN을
설정한다. 닉네임에서 생성된 고정 결과로 임시 픽셀 캐릭터를 부여받고 로비에 입장한다.
로비에서 3주년 질문 하나에 답변하고 재접속해 수정할 수 있다. 진행자는 참가자 목록과
제출 여부를 확인하고 PIN을 초기화할 수 있다. 대화 기록 기반 캐릭터 생성은 이번 범위에서
제외하되 이후 입력 원천을 교체할 수 있어야 한다."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 처음 입장하고 내 캐릭터 만나기 (Priority: P1)

초대받은 참가자는 공통 초대 코드를 입력하고, 아직 사용되지 않은 닉네임과 자신만의
PIN을 설정한다. 서비스는 닉네임에 따라 늘 같은 모습의 임시 픽셀 캐릭터를 보여주고,
참가자는 캐릭터와 함께 행사 로비에 들어간다.

**Why this priority**: 누구인지 구분하고 다시 찾아올 수 있어야 이후의 기록 작성과 행사
참여가 가능하다. 캐릭터를 처음 만나는 순간은 이 서비스가 평범한 설문과 다르게 느껴지는
첫 장면이기도 하다.

**Independent Test**: 새 참가자가 초대 코드, 닉네임, PIN만으로 캐릭터를 받고 로비에
도착하는 과정을 단독으로 실행해 확인할 수 있다.

**Acceptance Scenarios**:

1. **Given** 유효한 초대 코드를 받은 새 참가자, **When** 사용되지 않은 닉네임과 유효한
   PIN을 설정하면, **Then** 참가자 전용 캐릭터가 생성되고 로비에 입장한다.
2. **Given** 같은 닉네임 입력값과 같은 캐릭터 생성 규칙, **When** 캐릭터를 다시 확인하면,
   **Then** 이전과 동일한 캐릭터가 표시된다.
3. **Given** 잘못된 초대 코드, **When** 입장을 시도하면, **Then** 참가자 정보는 생성되지
   않고 다시 시도할 방법이 안내된다.
4. **Given** 이미 등록된 닉네임, **When** 새 참가자로 등록하려 하면, **Then** 기존 참가자의
   기록을 덮어쓰지 않고 PIN으로 재입장하라는 안내가 표시된다.

---

### User Story 2 - 3주년 답변을 남기고 다시 고치기 (Priority: P2)

로비에 들어온 참가자는 준비된 3주년 질문 하나를 읽고 자신의 답변을 저장한다. 나중에
서비스를 나갔다가 돌아와도 같은 답변을 확인하고 수정할 수 있다.

**Why this priority**: 첫 번째 구현에서도 단순한 프로필 생성으로 끝나지 않고, 모임에 남을
실제 기록 하나를 완성해야 서비스의 핵심 가치를 확인할 수 있다.

**Independent Test**: 등록된 참가자가 질문에 답하고, 로그아웃 또는 새로고침 뒤 다시
입장해 기존 답변을 확인하고 수정하는 과정으로 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 로비에 입장한 참가자와 공개 중인 3주년 질문, **When** 유효한 답변을 저장하면,
   **Then** 저장 완료가 분명히 표시되고 로비의 제출 상태가 완료로 바뀐다.
2. **Given** 답변을 저장한 참가자, **When** 나갔다가 같은 닉네임과 PIN으로 다시 입장하면,
   **Then** 자신의 캐릭터와 기존 답변이 그대로 표시된다.
3. **Given** 기존 답변이 있는 참가자, **When** 내용을 수정해 저장하면, **Then** 수정된
   답변이 최신 기록으로 표시된다.
4. **Given** 저장할 수 없는 상태, **When** 참가자가 저장을 시도하면, **Then** 성공한 것처럼
   표시하지 않고 내용이 사라지지 않도록 다시 시도할 방법을 안내한다.

---

### User Story 3 - 진행 상황을 보고 참가자 돕기 (Priority: P3)

진행자는 별도의 관리자 권한으로 참가자 목록과 각 참가자의 답변 제출 여부를 확인한다.
참가자가 PIN을 잊었을 때 기존 PIN을 알아내지 않고도 새 PIN을 설정할 수 있게 초기화한다.

**Why this priority**: 소규모 행사에서는 한 사람의 입장 문제가 전체 진행을 늦출 수 있다.
진행자가 데이터에 직접 손대지 않고 현장에서 문제를 풀 수 있어야 한다.

**Independent Test**: 여러 참가자의 제출 상태를 다르게 만든 다음 관리자 목록의 표시가
일치하는지 확인하고, 한 참가자의 PIN 초기화부터 새 PIN 설정과 재입장까지 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 등록 및 미등록 답변이 섞인 참가자들, **When** 진행자가 목록을 열면,
   **Then** 각 닉네임과 캐릭터, 제출 여부가 실제 상태와 일치하게 표시된다.
2. **Given** PIN을 잊은 참가자, **When** 진행자가 해당 참가자의 PIN을 초기화하면,
   **Then** 기존 PIN은 더 이상 사용할 수 없고 참가자는 새 PIN을 설정할 수 있다.
3. **Given** 관리자 권한이 없는 참가자, **When** 관리자 기능이나 참가자 목록에 접근하려
   하면, **Then** 다른 참가자의 상태를 볼 수 없고 접근이 거부된다.

### Edge Cases

- 닉네임은 앞뒤 공백과 대소문자 차이만으로 중복 등록할 수 없다.
- 빈 닉네임, 허용 길이를 벗어난 닉네임, 표시하기 어려운 제어 문자는 거부한다.
- PIN이 형식에 맞지 않거나 확인 입력과 다르면 참가자를 생성하지 않는다.
- 반복해서 잘못된 초대 코드나 PIN을 입력하면 잠시 기다린 뒤 다시 시도하도록 제한한다.
- 캐릭터 생성 규칙이 바뀌기 전에는 브라우저나 기기가 달라도 동일한 닉네임에 같은
  캐릭터가 표시된다.
- 참가자가 저장 도중 새로고침하거나 연결이 끊기면 마지막으로 성공한 답변을 유지한다.
- 진행자가 PIN을 초기화한 상태에서 기존에 열려 있던 참가자 화면은 보호된 기능을 계속
  사용할 수 없다.
- 질문이 아직 공개되지 않았으면 참가자는 빈 작성 화면 대신 준비 중이라는 상태를 본다.
- 참가자가 없는 경우 관리자 목록은 오류가 아니라 빈 상태와 다음 행동을 보여준다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 서비스는 유효한 공통 초대 코드를 입력한 사람에게만 참가자 등록과 재입장을
  허용해야 한다.
- **FR-002**: 새 참가자는 고유한 닉네임과 개인 PIN을 설정할 수 있어야 한다.
- **FR-003**: 닉네임은 앞뒤 공백과 대소문자 차이를 정규화한 뒤에도 참가자 간 고유해야
  한다.
- **FR-004**: PIN은 숫자 4~8자리로 받고, 저장하거나 표시할 때 원래 값을 노출해서는 안 된다.
- **FR-005**: 등록된 참가자는 닉네임과 PIN을 사용해 자신의 기존 상태로 재입장할 수 있어야
  한다.
- **FR-006**: 잘못된 초대 코드와 PIN 입력은 일정 횟수 반복되면 일시적으로 추가 시도를
  제한해야 한다.
- **FR-007**: 서비스는 정규화된 닉네임으로부터 참가자별 고정 캐릭터를 만들고, 같은 생성
  규칙이 유지되는 동안 기기나 접속 시점과 관계없이 동일한 모습을 보여줘야 한다.
- **FR-008**: 캐릭터 기록은 참가자 신원과 분리된 생성 입력 및 생성 규칙 버전을 구분할 수
  있어야 하며, 향후 대화 기반 입력으로 전환해도 기존 참가자 기록을 잃지 않아야 한다.
- **FR-009**: 참가자는 자신의 닉네임, 캐릭터, 질문 답변 상태를 로비에서 확인할 수 있어야
  한다.
- **FR-010**: 서비스는 한 번에 하나의 3주년 질문을 참가자에게 제공해야 한다.
- **FR-011**: 답변은 공백을 제외하고 1자 이상 1,000자 이하로 작성할 수 있어야 한다.
- **FR-012**: 참가자는 자신의 답변을 저장하고, 다시 접속한 뒤에도 확인하고 수정할 수
  있어야 한다.
- **FR-013**: 답변 저장 성공과 실패는 서로 혼동되지 않는 상태와 문장으로 알려야 한다.
- **FR-014**: 저장 실패 시 입력 중인 내용과 마지막으로 성공한 저장본을 임의로 잃어서는
  안 된다.
- **FR-015**: 참가자는 다른 참가자의 답변이나 제출 상태를 볼 수 없어야 한다.
- **FR-016**: 진행자는 별도의 관리자 권한을 확인받은 뒤 관리자 기능을 사용할 수 있어야
  한다.
- **FR-017**: 진행자는 참가자별 닉네임, 캐릭터, 답변 제출 여부를 한 목록에서 확인할 수
  있어야 한다.
- **FR-018**: 진행자는 기존 PIN을 확인하지 않고 참가자의 PIN을 초기화할 수 있어야 한다.
- **FR-019**: PIN 초기화 즉시 기존 PIN과 기존 참가자 접근 권한은 무효화되어야 하며,
  참가자는 진행자의 도움을 받아 새 PIN을 설정할 수 있어야 한다.
- **FR-020**: 참가자 프로필, 캐릭터, 답변, 제출 상태는 페이지 새로고침, 서비스 재시작,
  재배포 이후에도 보존되어야 한다.
- **FR-021**: 참가자용 핵심 흐름은 작은 휴대폰 화면과 터치 입력으로 완결할 수 있어야 하며,
  주요 입력과 버튼은 키보드로도 조작할 수 있어야 한다.
- **FR-022**: 서비스는 초대 코드, PIN, 세션 정보, 비공개 답변 전문을 진단 기록에 남겨서는
  안 된다.

### Key Entities

- **행사**: 3주년 모임의 입장 상태를 나타낸다. 행사 이름, 공통 초대 검증 정보, 현재
  질문, 참가 가능 여부를 가진다.
- **참가자**: 행사에 등록된 사람이다. 고유 닉네임, PIN 검증 정보, 캐릭터, 답변 상태와
  연결된다.
- **캐릭터 프로필**: 참가자에게 표시되는 픽셀 캐릭터 결과다. 생성 입력의 종류, 생성 규칙
  버전, 결정된 외형을 포함하며 참가자 기록과 독립적으로 다시 생성할 수 있다.
- **3주년 질문**: 이번 구간에서 참가자에게 제공하는 단일 질문이다. 질문 문구와 공개 상태를
  가진다.
- **답변**: 한 참가자가 3주년 질문에 남긴 최신 기록이다. 내용, 최초 저장 시점, 최근 수정
  시점과 제출 상태를 가진다.
- **관리자 접근 권한**: 진행자가 참가자 목록 확인과 PIN 초기화를 수행할 수 있음을 나타낸다.

### Scope Boundaries

**이번 구간에 포함**:

- 공통 초대 코드 입장
- 닉네임과 PIN을 이용한 등록 및 재입장
- 닉네임 기반의 고정 임시 캐릭터
- 행사 로비와 단일 3주년 질문
- 답변 저장 및 수정
- 참가자 목록, 제출 여부 확인, PIN 초기화

**이번 구간에서 제외**:

- 단톡방 대화 파일 업로드 또는 분석
- 대화 특징이나 해시를 이용한 최종 캐릭터 생성
- 참가자 간 답변 공개와 익명 답변
- 지식 및 아이디어 공유 카드
- 미니게임, 점수, 순위, 실시간 진행
- 이미지 업로드, 자유로운 캐릭터 꾸미기와 캐릭터 이동
- 여러 행사 또는 여러 질문 운영
- 행사 종료 후 엔딩 페이지

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 처음 방문한 참가자의 90% 이상이 별도 설명 없이 2분 안에 등록을 마치고
  자신의 캐릭터가 표시된 로비에 도착한다.
- **SC-002**: 등록된 참가자의 95% 이상이 3분 안에 질문을 읽고 답변을 저장한 뒤 완료
  상태를 확인한다.
- **SC-003**: 답변을 저장한 참가자 100%가 다른 브라우저나 새 접속에서도 자신의 기존
  캐릭터와 최신 답변을 다시 확인할 수 있다.
- **SC-004**: 동일한 정규화 닉네임과 동일한 생성 규칙으로 100회 반복 확인했을 때 캐릭터
  결과가 모두 동일하다.
- **SC-005**: 최대 30명의 참가자가 5분 안에 입장과 답변 저장을 동시에 수행해도 참가자
  또는 답변 기록이 서로 바뀌거나 사라지지 않는다.
- **SC-006**: 진행자는 참가자 목록에서 제출하지 않은 사람을 30초 안에 찾고, 요청받은
  참가자의 PIN을 1분 안에 초기화할 수 있다.
- **SC-007**: 유효한 초대 정보나 관리자 권한이 없는 사용자는 보호된 참가자 기록과 관리자
  목록을 열람할 수 없다.
- **SC-008**: 저장 실패, 잘못된 입장 정보, PIN 초기화 상태를 만난 테스트 참여자 전원이
  별도 문의 없이 화면 안내만으로 다음 행동을 선택할 수 있다.
- **SC-009**: 360픽셀 너비의 화면과 키보드 전용 조작에서 등록, 재입장, 답변 작성·수정의
  모든 핵심 동작을 완료할 수 있다.

## Assumptions

- 한 번의 3주년 행사와 최대 30명의 초대된 참가자를 대상으로 한다.
- 모든 참가자는 행사 진행자가 별도로 전달한 같은 초대 코드를 알고 있다.
- 닉네임은 참가자가 선착순으로 등록하며, 이번 구간에서는 등록 후 직접 변경하지 않는다.
- 참가자는 개인 PIN을 기억할 책임이 있고, 잊은 경우 진행자에게 직접 초기화를 요청한다.
- 진행자는 한 명이며 관리자 접근 정보는 서비스 설정 단계에서 별도로 전달받는다.
- 3주년 질문 문구는 행사 전에 준비되며, 이번 구간에서는 진행자가 화면에서 여러 질문을
  만들거나 순서를 바꾸지 않는다.
- 답변은 작성자 본인에게만 보이고, 다른 참가자에게 공개하는 기능은 후속 구간에서 정한다.
- 캐릭터는 현재 닉네임에서 만들어지지만, 대화 기반 생성으로 바뀌는 시점과 기존 캐릭터의
  유지 여부는 별도 기능 명세에서 결정한다.
- 참가자는 서비스 이용 중 일반적인 모바일 네트워크 연결을 사용할 수 있다.
