# Feature Specification: 질문별 답변 공개 진행

**Feature Branch**: `미생성 (before_specify 훅 없음)`

**Created**: 2026-08-31

**Status**: Draft

**Input**: User description: "3주년 질문 네 개를 정해진 순서로 공개한다. 질문 하나를 연 뒤에는 그 질문의 답변을 하나씩 공개하고, 각 답변의 작성자를 바로 공개한다. 해당 질문의 모든 답변이 끝난 뒤에만 다음 질문으로 넘어간다."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 첫 질문부터 답변을 순서대로 공유하기 (Priority: P1)

진행자는 첫 질문인 "3주년에 대한 감상이나 소감"을 참석자에게 먼저 보여 준다. 답변 하나를
공개하고, 바로 그 답변을 쓴 사람의 닉네임과 캐릭터를 공개한다. 남은 답변도 같은 순서로
반복해 그 질문의 답변을 모두 함께 본다.

**Why this priority**: 이번 질답 시간의 중심은 추리나 점수가 아니라 서로가 남긴 말을 편하게
읽는 데 있다. 답과 작성자를 연달아 보여 주는 흐름이 가장 단순하고 진행 중에도 헷갈리지 않는다.

**Independent Test**: 첫 질문에 답변을 세 개 제출한 행사에서 질문을 열고, 세 답변 각각을
답변 공개 뒤 작성자 공개 순서로 모두 마치는 과정을 실행해 확인할 수 있다.

**Acceptance Scenarios**:

1. **Given** 질답 시간이 시작되기 전, **When** 진행자가 첫 질문을 시작하면, **Then** 첫
   질문 문구와 답변을 공개할 준비 상태만 참석자 화면에 표시된다.
2. **Given** 첫 질문에 아직 공개하지 않은 답변이 있을 때, **When** 진행자가 다음 답변을
   공개하면, **Then** 그 답변 내용만 먼저 표시되고 작성자 정보는 표시되지 않는다.
3. **Given** 답변 내용을 표시 중일 때, **When** 진행자가 작성자 공개를 선택하면, **Then**
   같은 답변과 함께 그 답변을 제출한 참가자의 닉네임과 캐릭터가 표시된다.
4. **Given** 한 답변의 작성자를 공개한 상태, **When** 진행자가 다음 답변으로 이동하면,
   **Then** 다음 답변은 다시 작성자 정보가 숨겨진 상태로 시작한다.

### User Story 2 - 질문 하나를 끝낸 뒤 다음 질문으로 넘어가기 (Priority: P2)

참가자는 행사 전에 네 질문의 답변을 모두 저장한다. 진행자는 현재 질문의 제출 답변을 모두 공개한 뒤에만 다음 질문을 연다. 질문은 행사 전에
정한 순서인 3주년 감상·소감, 지식·아이디어 공유, 올해의 좋은 일 자랑, 더 하고 싶은 말대로
진행된다. 이미 끝낸 질문으로 돌아가 다시 보여 줄 수는 있지만, 아직 열지 않은 질문이나 그
답변은 참석자 화면에 먼저 나타나지 않는다.

**Why this priority**: 질문이 섞이면 답변을 읽는 흐름이 끊긴다. 한 질문을 다 보고 다음
주제로 넘어가면 이야기의 결도 바뀌는 게 자연스럽고, 진행자도 현재 위치를 바로 알 수 있다.

**Independent Test**: 네 질문에 각각 제출 답변을 준비하고, 첫 질문을 완전히 공개하기 전에는
두 번째 질문으로 넘어갈 수 없으며, 첫 질문 완료 뒤에는 두 번째 질문을 열 수 있는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 현재 질문에 작성자까지 공개하지 않은 답변이 남아 있을 때, **When** 진행자가
   다음 질문으로 넘어가려 하면, **Then** 남은 답변 수와 현재 질문을 끝내야 한다는 안내를
   보여 주고 질문을 전환하지 않는다.
2. **Given** 현재 질문의 모든 답변을 작성자 공개까지 마쳤을 때, **When** 진행자가 다음
   질문 열기를 선택하면, **Then** 다음 순서의 질문 문구와 대기 상태가 표시된다.
3. **Given** 두 번째 질문을 진행 중일 때, **When** 참석자가 발표 화면을 보면, **Then** 세
   번째와 네 번째 질문의 문구, 답변, 작성자 정보는 보이지 않는다.
4. **Given** 행사 진행 중 이전 질문의 답변을 다시 보고 싶은 상황, **When** 진행자가 완료된
   질문을 관리자 화면에서 확인하면, **Then** 원래 공개 이력과 작성자 공개 상태를 잃지 않고
   확인할 수 있으며 현재 프로젝터 화면의 질문 순서는 바뀌지 않는다.

### User Story 3 - 마지막까지 마치고 질답 시간을 닫기 (Priority: P3)

진행자는 네 번째 질문인 "더 하고 싶은 말"까지 같은 방식으로 모두 공개한다. 마지막 답변의
작성자를 공개하면, 아직 공개하지 않은 답변이 남지 않았다는 마무리 상태를 화면에서 확인한다.
이 상태가 된 뒤 로그인한 참가자는 자신의 기기에서 네 질문의 모든 답변과 작성자를 다시 볼 수 있다.

**Why this priority**: 진행자가 끝난 줄 알고 중간에 멈추거나, 마지막 답변을 놓치는 일을
막아야 한다. 모임의 끝을 별도 게임이나 투표 없이 담백하게 정리하기 위한 상태다.

**Independent Test**: 네 번째 질문의 마지막 답변까지 작성자를 공개한 뒤, 완료 화면이 나타나고
다시 확인할 수 있는 답변이 남지 않았음을 확인한다.

**Acceptance Scenarios**:

1. **Given** 네 번째 질문의 모든 답변을 작성자 공개까지 마친 상태, **When** 진행자가
   질답 진행 화면을 확인하면, **Then** 전체 질답 시간이 완료됐다는 상태와 질문별 완료
   현황을 확인할 수 있다.
2. **Given** 어떤 질문에 제출된 답변이 없을 때, **When** 진행자가 그 질문을 시작하면,
   **Then** 빈 답변 목록 대신 제출된 답변이 없다는 안내를 표시하고 다음 질문으로 넘어갈 수
   있다.
3. **Given** 전체 질답이 완료된 상태, **When** 로그인한 참가자가 질답 기록 화면을 열면,
   **Then** 네 질문의 공개 답변과 작성자 정보를 질문별로 모두 볼 수 있다.

### Edge Cases

- 질문별 답변 수가 다르거나 답변이 하나뿐이어도, 답변 공개와 작성자 공개를 각각 거친 뒤
  해당 질문을 완료로 처리한다.
- 현재 질문에 답변이 없으면 진행자는 빈 상태를 확인한 뒤 다음 질문으로 전환할 수 있다.
- 답변이나 작성자 공개 직후 페이지를 새로고침해도 현재 질문, 현재 답변, 작성자 공개 여부와
  질문별 완료 상태를 복구한다.
- 행사 시작 전에 참가자가 네 답변 중 일부만 저장했으면, 저장하지 않은 질문에는 답변이 없는
  상태로 진행한다. 행사 중 답변 작성·수정은 허용하지 않는다.
- 진행자는 작성자 공개 전에 실수로 다음 답변으로 넘어갈 수 없으며, 현재 답변의 작성자를
  공개하거나 현재 답변을 발표에서 제외하는 명시적 결정을 해야 한다.
- 답변의 긴 줄, 링크, 이모지는 질문 진행 화면과 발표 화면에서 내용이 잘리거나 다른 요소를
  가리지 않게 표시한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 서비스는 행사 질답을 다음 네 질문의 고정 순서로 제공해야 한다: 3주년에 대한
  감상이나 소감, 지식·아이디어 공유, 올해의 좋은 일 자랑하기, 더 하고 싶은 말.
- **FR-002**: 참가자는 행사 시작 전에 네 질문을 모두 읽고, 질문마다 자신의 최신 답변을
  저장할 수 있어야 한다.
- **FR-003**: 진행자는 현재 질문을 참석자에게 공개하기 전에 질문 문구와 시작 전 상태를
  확인할 수 있어야 한다.
- **FR-004**: 진행자는 현재 질문의 제출 답변을 한 번에 하나씩 선택해 공개할 수 있어야 한다.
- **FR-005**: 답변을 처음 공개할 때는 답변 내용만 표시하고 작성자의 닉네임과 캐릭터는
  숨겨야 한다.
- **FR-006**: 진행자는 현재 답변을 공개한 뒤 별도의 명시적 동작으로 그 답변의 작성자
  닉네임과 캐릭터를 공개할 수 있어야 한다.
- **FR-007**: 작성자 공개를 마친 답변만 해당 질문의 공개 완료 답변으로 처리해야 한다.
- **FR-008**: 진행자는 현재 답변의 작성자 공개를 마치기 전에는 다음 답변으로 이동할 수
  없어야 한다. 단, 진행자가 해당 답변을 발표에서 제외한다는 명시적 결정을 한 경우에는
  다음 답변으로 이동할 수 있어야 한다.
- **FR-009**: 서비스는 현재 질문의 모든 제출 답변이 공개 완료되기 전에는 다음 질문 전환을
  막고, 남은 답변 수를 진행자에게 알려야 한다.
- **FR-010**: 현재 질문의 답변을 모두 공개 완료했거나 제출 답변이 없음을 확인한 경우에만
  진행자는 다음 순서의 질문을 공개할 수 있어야 한다.
- **FR-011**: 아직 시작하지 않은 질문과 그 답변·작성자 정보는 진행자 외 참석자 화면에
  표시해서는 안 된다.
- **FR-012**: 진행자는 완료된 이전 질문과 그 답변을 관리자 화면에서 다시 확인할 수 있어야
  하며, 기존 질문 순서와 프로젝터 화면의 현재 질문은 유지되어야 한다.
- **FR-013**: 서비스는 질문별 시작 여부, 답변별 답변 공개·작성자 공개·제외 여부, 현재
  질문과 현재 답변을 새로고침·서비스 재시작·재배포 뒤에도 보존해야 한다.
- **FR-014**: 발표 화면은 진행자 조작 요소와 아직 공개하지 않은 답변 목록을 보이지 않게
  하고, 현재 질문·현재 답변·공개된 작성자 정보만 읽기 쉽게 표시해야 한다.
- **FR-015**: 질답 진행의 주요 동작은 명확한 텍스트 라벨, 키보드 조작, 보이는 포커스 상태를
  제공해야 한다.
- **FR-016**: 전체 질답이 완료되기 전 관리자 권한이 없는 사람은 질문별 전체 답변 목록, 진행 상태, 아직 공개되지 않은
  답변과 작성자 정보를 볼 수 없어야 한다.
- **FR-017**: 전체 질답이 완료된 뒤에는 로그인한 참가자만 질문별 공개 답변과 작성자를 열람할 수 있어야 한다.
- **FR-018**: 이 기능은 공개 진행 상태만 관리하며 참가자가 제출한 원본 답변을 수정하거나
  삭제해서는 안 된다.
- **FR-019**: 이번 질답 흐름에는 투표, 작성자 추측 게임, 점수, 순위, 자동 추첨을 포함하지
  않아야 한다.

### Key Entities

- **질답 순서**: 행사에서 질문을 여는 고정된 순서와 현재 진행 위치를 나타낸다.
- **질문 진행 상태**: 질문별 시작·진행·완료 여부, 답변 수와 완료 답변 수를 나타낸다.
- **답변 발표 항목**: 원본 답변을 발표에 사용한 상태다. 답변 공개 여부, 작성자 공개 여부,
  발표 제외 여부와 공개 순서를 가진다.
- **발표 화면 상태**: 참석자에게 지금 보여 줄 질문, 답변, 작성자 공개 여부, 대기 또는 완료
  상태를 나타낸다.
- **완료 후 질답 기록**: 전체 질답이 완료된 뒤 참가자에게 보이는 질문별 답변과 작성자 목록이다.

### Scope Boundaries

**이번 구간에 포함**:

- 네 개의 고정 3주년 질문과 질문별 공개 순서
- 질문 공개 후 답변 공개, 작성자 공개를 반복하는 진행
- 현재 질문의 모든 답변을 마친 뒤 다음 질문으로 전환하는 제어
- 질문별 완료 현황, 이전 질문 재확인, 마지막 완료 상태
- 진행자용 조작 화면과 참석자용 발표 화면의 안전한 분리
- 전체 완료 뒤 로그인한 참가자의 질문별 질답 기록 열람

**이번 구간에서 제외**:

- 작성자 맞히기 투표나 미니게임
- 질문을 행사 중 새로 만들거나 순서를 바꾸는 기능
- 답변 추천, 순위, 좋아요, 감정 분석이나 자동 요약
- 행사 진행 중 참가자가 다른 참가자의 답변을 탐색하는 기능
- 공개 링크, 로그인하지 않은 사람의 열람, 외부 공유

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 처음 사용하는 진행자는 별도 설명 없이 1분 안에 첫 질문을 열고 답변 하나를
  공개한 뒤 작성자를 공개할 수 있다.
- **SC-002**: 질문마다 최대 30개의 답변이 있을 때, 진행자는 모든 답변을 답변 공개와 작성자
  공개 순서로 빠뜨리지 않고 완료 현황에서 확인할 수 있다.
- **SC-003**: 미완료 답변이 하나라도 있는 질문에서 다음 질문 전환 시도는 100% 차단되고,
  진행자는 남은 답변 수를 확인할 수 있다.
- **SC-004**: 각 질문을 완료한 뒤에는 네 질문이 정한 순서대로만 다음 질문을 열 수 있다.
- **SC-005**: 진행 도중 페이지를 새로고침하거나 서비스를 재시작·재배포해도 질문 위치,
  현재 발표 내용, 답변별 공개 상태가 100% 복구된다.
- **SC-006**: 1,366×768 이상 발표 화면에서 질문과 최대 1,000자 답변, 공개된 닉네임과
  캐릭터를 겹침이나 내용 손실 없이 읽을 수 있다.
- **SC-007**: 관리자 권한이 없는 접근 시도에서는 아직 시작하지 않았거나 아직 공개하지 않은
  답변과 작성자 정보가 한 건도 노출되지 않는다.
- **SC-008**: 답변이 없는 질문, 마지막 질문 완료, 새로고침 뒤 복구 상태를 만난 테스트
  진행자 전원이 화면 안내만으로 다음 행동을 고를 수 있다.
- **SC-009**: 전체 완료 뒤 로그인한 참가자는 1분 안에 네 질문의 답변과 작성자를 모두 열람할 수 있다.

## Assumptions

- 기존 행사 기본 흐름의 단일 답변 작성 화면은 네 질문 답변 작성 화면으로 확장한다.
- 기존 결과 발표 기능의 진행 상태와 발표 화면을 확장해 여러 질문의 진행을 관리한다.
- 질문 문구와 순서는 행사 전에 확정하며 이번 행사에서는 변경하지 않는다.
- 참가자 한 명은 행사 시작 전 질문마다 하나의 최신 답변을 제출할 수 있고, 각 질문의 답변은 최대 1,000자다.
- 기본 진행자는 한 명이다. 같은 진행자가 실수로 답변을 넘겼을 때를 대비해, 답변 공개 전
  제외 결정을 분명히 남긴다.
- 이 시간은 투표나 경쟁보다 답변과 작성자를 차례로 함께 보는 공유 시간이다.
- 전체 완료 후 질답 기록은 참가자 로그인 세션 안에서만 열람하며 외부 공개 링크는 제공하지 않는다.
